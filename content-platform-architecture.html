Your team runs a Content Platform. Product teams publish web pages (title, body, metadata) that apps fetch over a REST API.

Today: One team publishes from an internal admin UI (writes to your platform).

Architecture Overview

Three independent paths — ingestion, storage, and read — connected by a canonical data model. New teams plug in without touching core logic.

📝 Ingestion

Adapters normalize any external source into a canonical model. Webhooks from Contentful, internal admin UI, or future CMSs all converge to one Lambda.

🗄️ Storage

DynamoDB single table stores metadata and version pointers. S3 stores large HTML bodies. Separate concerns, optimal cost, no size limits.

🚀 Read API

FastAPI on Lambda serves content by ID and locale in O(1) time. Immutable versions guarantee consistency; latest pointers guarantee speed.

Storage Layer

DynamoDB single table + S3. Denormalized for reads, immutable for history, and partitioned by locale for independent publishing.

Figure 2: Data Model — DynamoDB Single Table + S3 Object Hierarchy
🔑 Schema Design Rationale

Two access patterns supported: immutable version history and O(1) latest lookup.

PK (Partition Key) SK (Sort Key) Purpose Attributes
CONTENT#<id> LOCALE#<locale>#VERSION#<v> Immutable version history title, bodyS3Key, metadata, publishedAt, version
CONTENT#<id>#LATEST LOCALE#<locale> O(1) latest lookup title, bodyS3Key, metadata, publishedAt, version

Why These Decisions Matter

Decision Best Practice Why It Matters
Dual-write (version + latest) Denormalization Reads are 20 QPS today but could be 20,000 tomorrow. A GetItem on CONTENT#id#LATEST is O(1) and costs 0.5 RCU.
Immutable versions Event Sourcing You never UPDATE a version row. Append-only gives a complete audit trail and eliminates concurrency bugs.
S3 for body, DDB for metadata Right-size Stores DynamoDB items have a 400 KB limit. Offloading blobs to S3 avoids size limits and reduces storage cost by ~90%.
Locale in SK Multi-tenancy de-DE and en-US publish independently. Add fr-FR tomorrow with zero schema changes.
On-Demand Capacity Pay-per-request At 10 writes/day, provisioned capacity costs more to manage than the data itself. On-demand handles spikes automatically.

🔌 The Canonical Model

Every external source translates into this model. The ingestion Lambda only understands this shape.

class CanonicalContent(BaseModel):
    content_id: str          # Your platform's ID
    locale: str              # "en-US", "de-DE"
    title: str
    body: str                # Raw HTML/Markdown
    metadata: dict
    source: str             # "internal", "contentful"
    external_id: Optional[str] = None
🧩 Adapter Pattern
class ContentAdapter(ABC):
    @abstractmethod
    def normalize(self, payload: dict, headers: dict) -> CanonicalContent:
        pass

    @abstractmethod
    def verify(self, payload: dict, headers: dict) -> bool:
        """Webhook signature validation."""
        pass

class InternalAdapter(ContentAdapter):
    # Admin UI already speaks our format
    def normalize(self, payload, headers): ...

class ContentfulAdapter(ContentAdapter):
    # Maps Contentful fields, resolves locales
    def normalize(self, payload, headers): ...
    def verify(self, payload, headers):
        # Verify Contentful webhook signature
        ...
⚙️ Ingestion Lambda Handler
def handler(event, context):
    route = event['path']  # /ingest or /webhook/contentful
    payload = json.loads(event['body'])
    headers = event['headers']

    # 1. Select adapter by route
    adapter = adapter_factory.get(route)

    # 2. Verify webhook signature
    if not adapter.verify(payload, headers):
        return {'statusCode': 401}

    # 3. Normalize to canonical model
    content = adapter.normalize(payload, headers)

    # 4. Generate version
    version = generate_version(content.content_id, content.locale)

    # 5. Write body to S3 FIRST
    s3_key = f"bodies/{content.content_id}/{content.locale}/{version}/body.html"
    s3.put_object(Bucket=BUCKET, Key=s3_key, Body=content.body)

    # 6. Atomic transaction: version + latest pointer
    ddb.transact_write_items(
        TransactItems=[
            {'Put': {'TableName': TABLE, 'Item': {
                'PK': f'CONTENT#{content.content_id}',
                'SK': f'LOCALE#{content.locale}#VERSION#{version}',
                'title': content.title,
                'bodyS3Key': s3_key,
                'metadata': content.metadata,
                'publishedAt': now,
                'version': version,
                'source': content.source
            }}},
            {'Put': {'TableName': TABLE, 'Item': {
                'PK': f'CONTENT#{content.content_id}#LATEST',
                'SK': f'LOCALE#{content.locale}',
                'title': content.title,
                'bodyS3Key': s3_key,
                'metadata': content.metadata,
                'publishedAt': now,
                'version': version
            }}}
        ]
    )

    return {'statusCode': 200}

Ingestion Best Practices

Decision Best Practice Why It Matters
Adapter Pattern Strategy / OCP New sources (Sanity, Strapi) are a config + adapter file. Zero changes to Lambda handler, DDB schema, or read API.
TransactWriteItems Atomic Consistency Version history and latest pointer are written together. A crash never leaves a dangling pointer.
Idempotency via version key Exactly-once Contentful retries on timeout. Deterministic DDB keys make re-delivery a no-op.
S3 write BEFORE DDB Storage Ordering If S3 fails, abort before touching DDB. If DDB fails, you have an orphaned S3 object (cheap, cleanup via lifecycle rules).

Read API

FastAPI on Lambda with O(1) lookups. Separate from ingestion for independent scaling and security.

Figure 4: Read Flow — O(1) Lookup via Latest Pointer + S3 Body Fetch
🐍 FastAPI + Mangum
from fastapi import FastAPI, HTTPException, Query
from mangum import Mangum
import boto3

app = FastAPI(title="Content Platform API")
ddb = boto3.resource('dynamodb')
table = ddb.Table('ContentPlatform')
s3 = boto3.client('s3')

@app.get("/content/{content_id}")
async def get_content(
    content_id: str,
    locale: str = Query(default="en-US", pattern=r'^[a-z]{2}-[A-Z]{2}$')
):
    # O(1) lookup of latest version
    response = table.get_item(Key={
        'PK': f'CONTENT#{content_id}#LATEST',
        'SK': f'LOCALE#{locale}'
    })

    item = response.get('Item')
    if not item:
        raise HTTPException(status_code=404, detail="Content not found")

    # Fetch body from S3
    body_obj = s3.get_object(Bucket=BUCKET, Key=item['bodyS3Key'])
    body = body_obj['Body'].read().decode('utf-8')

    return {
        "id": content_id,
        "locale": locale,
        "version": item['version'],
        "title": item['title'],
        "body": body,
        "metadata": item['metadata'],
        "publishedAt": item['publishedAt']
    }

# Lambda entry point
handler = Mangum(app, lifespan="off")
⚡ FastAPI + Mangum

Pydantic validation, OpenAPI docs, and async I/O on Lambda. Mangum wraps ASGI for Lambda without code changes.

🌍 Locale as Query Param

Existing callers without ?locale= default to en-US. New locales require no URL path changes.

🔒 CQRS-lite

The read API never writes. The ingestion Lambda never reads for clients. Optimize, scale, and secure each path independently.

🔁 Async boto3

Prevents blocking the event loop during S3/DDB calls. Critical when scaling from 20 QPS to 2,000 QPS.

Contentful Onboarding

How Team 2 plugs in without a single line of core code changing. The Adapter Pattern in action.

Figure 5: Team 2 Onboarding Flow — Zero Core Rewrites

  • Receive Webhook Schema

    Contentful team shares their webhook payload structure and signing secret.

    Code change: None

  • Implement ContentfulAdapter

    Create adapters/contentful.py that maps Contentful fields to the canonical model.

    Code change: +1 file

  • Add API Gateway Route

    Register POST /webhook/contentful in API Gateway / SAM / Terraform.

    Code change: +1 route config

  • Share Webhook URL

    Provide the endpoint and secret to the Contentful team for their webhook configuration.

    Code change: None

  • Publish

    Contentful editor clicks "Publish" → webhook fires → content goes live instantly.

    Code change: None
🎯 The Principle at Work

Inversion of Control: Your platform defines the contract. External teams conform to it. You don't chase their schemas. If a third team comes with Sanity CMS next quarter — add adapters/sanity.py and a route. Done.

Scaling Path

Your Year-1 numbers are tiny, but the design is already ready. Here is what you add, not rewrite.

📊 DynamoDB Capacity

Now: On-Demand
At 2,000 QPS: Switch to Provisioned + Auto-Scaling via CloudWatch alarms.

⚡ API Caching

Now: Direct Lambda reads
At scale: CloudFront in front of API GW with max-age=60 on read responses.

🧠 Application Cache

Now: None
At scale: ElastiCache (Redis) or DAX to cache latest pointers for 30s.

🖥️ Compute

Now: Lambda
At scale: Fargate/ECS with FastAPI when cold starts hurt; ALB replaces API GW.

📡 Async Invalidation

Now: Optional EventBridge
At scale: EventBridge + SQS for async cache warming on every publish.

🔐 Security

Now: Basic IAM
At scale: Least-privilege IAM — Ingestion: DDB Write + S3 Put only. Read: DDB Read + S3 Get only.

✓ The Golden Rule

Nothing above changes the schema, the adapter pattern, or the API contract. The architecture scales by adding infrastructure, not rewriting logic.
